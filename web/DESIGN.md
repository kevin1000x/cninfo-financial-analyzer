# DESIGN.md — cninfo-analyzer-web 设计规范

本文件是前端界面的设计事实来源（source of truth）。改 UI 前先读这里；改了设计，先改这里。
后续会话可用 `interface-design` skill 依此执行；审查用 `web-design-guidelines` skill。

## 意图（Intent）

- **使用者**：做中国上市公司年报文本研究的分析师/研究生。打开这个页面是为了提交一批「股票代码 × 年份」的分析任务，可信地看到流水线进度，然后拿走 xlsx。一天会来多次。
- **核心动词**：提交 → 盯进度 → 下载结果。页面的一切层级为这条路径服务。
- **气质**：冷静、精确、高密度的**研究工作台**，像金融终端，不像营销页。拒绝蓝紫渐变、巨型 Hero、低信息密度的演示感。

## 领域（Domain）

巨潮公告 · 年报 PDF · MD&A 节选 · jieba 分词 · 情感测度（Tone）· Fog 可读性指数 · TNI 创新度 · 观测值（rows）· z-score 标准化 · SSE 流水线事件。

**色彩世界**：报告纸面白、打印油墨黑、行情屏墨绿、Excel 表头绿、公告红章、石墨灰、终端屏暗底。
**签名元素（Signature）**：「任务进度轨」——忠实于流式引擎的三段节奏（接收任务 → 逐份处理 k/N → 汇总导出），配当前任务指示条与终端式日志面板；等宽数字（tabular-nums）贯穿全部动态数值。
（注意：后端 web 路径 `run_streaming` 不输出批量路径的 `PHASE n:` 日志，进度轨必须依据 `[k/N]` 任务行与导出标记推导，不得照搬批量阶段。）

## 拒绝的默认（Rejected defaults)

1. 蓝紫渐变 / 装饰性大色块 → 纸面中性色 + 单一墨绿强调（60/30/10）。
2. 英文枚举值直接当文案（`annual` / `semi_annual`）→ 中文标签为主，mono 值作辅助。
3. 裸 `<pre>` 日志流 → 终端面板 + 级别配色 + 阶段轨。
4. 大圆角 + 重阴影的卡片堆叠 → 细边框 + 极轻阴影的工作台密度。

## Tokens

Tailwind v4 `@theme inline` 定义在 `src/index.css`，语义色随 `prefers-color-scheme` 翻转：

| Token | Light | Dark | 用途 |
| --- | --- | --- | --- |
| `canvas` | `#fafafa` | `#09090b` | 页面底 |
| `surface` | `#ffffff` | `#111113` | 卡片/面板 |
| `surface-2` | `#f4f4f5` | `#1b1b1f` | 输入/嵌入面（比表面略深 = 「可输入」） |
| `fg` / `fg-2` / `fg-3` / `fg-4` | zinc 950/600/500/400 | zinc 50/400/500/600 | 文本四级层次 |
| `border` | `rgba(0,0,0,.08)` | `rgba(255,255,255,.08)` | 发丝分隔 |
| `border-strong` | `rgba(0,0,0,.16)` | `rgba(255,255,255,.16)` | 控件描边 |
| `accent` | `#047857`（emerald-700 墨绿） | `#34d399`（emerald-400） | 主操作/进行中/品牌 |
| `accent-soft` | `#ecfdf5` | `rgba(16,185,129,.10)` | 强调底色 |
| `danger` / `warn` | red-600 / amber-600 | red-400 / amber-400 | 语义色，仅表意不装饰 |

- 深度策略：**细边框为主**，light 模式卡片加一层极轻阴影；dark 模式只靠边框分层。不混用。
- 圆角刻度：控件 6px（`rounded-md`）· 卡片 10px（`rounded-[10px]`）· 终端/大容器 12px。
- 间距基数 4px；面板内边距 16px，组间 12px，区块间 24–32px。

## 排版

- 字体：`Inter Variable`（拉丁/数字）+ 系统 CJK 栈（苹方/雅黑）；代码、股票代码、日志、计时用 `JetBrains Mono Variable`。
- 字阶（≈1.25，基准 14）：`11 caption · 12 meta · 14 body · 16 h3 · 20 h2 · 28 h1`。
- 层级靠**字重 + 颜色**，不只靠字号：600 主值 / 500 标签 / 400 辅助，配合 fg 四级。
- 全部动态数字（计数、计时、rows）加 `tabular-nums`；标题 `text-balance`，正文 `text-pretty`。

## 动效

- 只动 `transform` / `opacity`，绝不 `transition: all`；时长 120–200ms。
- 缓动统一 `cubic-bezier(0.23, 1, 0.32, 1)`（ease-out 族），入场不用 ease-in；按压 `scale(.97)`。
- 新日志行：120ms 淡入 + 4px 上移；状态点运行中呼吸；全部尊重 `prefers-reduced-motion`。
- 高频操作（取消、重置）不加动画延迟。

## 状态清单（缺一个都不算完成）

- 交互件：default / hover / active / focus-visible / disabled。
- 数据区：连接中（replay 提示）/ 运行中 / 已完成 / 失败 / 已取消 / 空态。
- 表单：行内校验错误 + 提交中 loading；提交按钮在请求发出前保持可用。

## 第二个视图：结论核查（`#/audit`）

站点现在托两个视图，共用外壳与 tokens，**不共用后端、数据源，也不共用主张**：

| | 批量分析（`#/`） | 结论核查（`#/audit`） |
| --- | --- | --- |
| 后端 | cninfo 流水线 `/api/proxy/*`，有状态任务、单任务、SSE | finaudit `/api/audit/*`，**无状态请求–响应** |
| 核心动词 | 提交 → 盯进度 → 下载 | 粘一段结论 → **逐条判定** → 每条把来路交出去 |
| 焦点 | 任务进度轨 | **那张逐条判定表，以及每条下面「拿哪几个数算出来的」** |

导航是**真链接 + URL hash**，不是路由库：`<a href>` 才让 Cmd 点击、中键、后退键正常。

### 意图（Intent）

- **使用者**：**手上有一个别人给的结论、而他要为它负责的人**。那个结论可能来自券商 AI、
  问财、雪球，或者任何一个大模型。他 5 分钟前拿到这段话，5 分钟后要决定信不信它，
  **并且会被追问「你凭什么信」**。
  ⚠️ 2026-09-11 由「提问的人」改为「拿到一个结论的人」（`D-041`）——
  提问那个角色没有消失：**核查是问答的超集**，同一个输入框，不带数就是提问。
- **气质**：**审计底稿**，不是仪表盘。冷、密、可引用。沿用工作台既有的中性纸面 + 单一墨绿强调。

### 签名元素（Signature）

**「可独立核验的锚点」**：答案旁边摆着年报 PDF 的 SHA-256，配一句「去巨潮下同一份年报算一遍，对得上」。
别的财务问答产品没有这一栏，因为它们给不出。

### 这一页刻意为之的五条（它们是设计约束，不是文案偏好）

1. **覆盖面先于输入框。** 产品最致命的错是把覆盖面装大：看起来什么公司都能问，然后对一家没有数据的公司给出一个数。所以范围限定放在第一屏 —— 和审计报告把范围限定写在开头、而不是附注最后，是同一个本能。
2. **真实年报与合成夹具必须分得开，且不能只靠颜色。** 真实 = 实线 `border-strong`；合成 = **虚线** + amber 底 + 一枚「不是真实公司」的 warn chip。合成夹具**不显示公司简称** —— 夹具里的「公司名」是虚构的，显示出来等于请人去搜一家不存在的公司。
3. **答案卡正文逐字是服务端渲染的纯文本。** 浏览器侧不重排、不解析、不「优化」。人读的表达契约只有一套，在服务端；这里再渲染一版，就是对外展示一个没人复核过的版本。⇒ 用 `log-scroll` + `whitespace-pre-wrap`，保留服务端自己的缩进（缩进承载层级）。

4. **第一行必须写「我把这段话读成什么」。** 系统会自己判这段话是提问还是待核声明
   （判据：有没有一个没被主体/期间消耗掉的数值）。**判错了不能藏** ——
   与证据页印 `metric_resolved_by` / `matched_alias` 是同一个做法。
   承接上下文（「主体 600519、期间 2023 年 承自前一句」）同理，必须印出来：
   系统若承接错了公司或年份，这一行是读者唯一看得见的地方。

5. 🔴 **「核不了」不能漆成红叉。** `NOT_COVERED` 与 `NOT_CHECKABLE` 是**成功的判定**，
   不是错误。覆盖面窄是刻意选的取舍，换来的是每一个能核的数都有人逐字段签过字 ——
   把它标成红色，等于把这个取舍卖成一个缺陷。
   ⇒ chip 用 `neutral`，记号用 `—` / `·`。**红色只留给 `INCONSISTENT`**：
   那才是这一页真正要抬出来的发现。服务端 `_MARK` 与这里必须一致，
   两边不一致时以「它是正当输出」这句话为准（2026-09-11 并排一看就露出来了）。

### 页面上不许出现的说法

**「经复核验证」「一致率 xx%」这类话一律不许写。** 证据链的人读复核实验（H2）尚未通过：
复核者指出的缺口补了，但**补完之后的读数没有人测过**。声称一个手上没有的结果，
正是这个产品存在的理由所要防的那件事。

可以说它**做了什么**（每个答案带可独立复核的证据链），不能说它**被证明了什么**。

### 两处窄屏实测发现（375px）

- 答案是一个 30 位十进制数。28px 字号下要 483px 宽，会被卡片的 `overflow-hidden` 裁掉 —— 而它是整页的焦点，裁掉等于把答案藏起来；又不能四舍五入（服务端给多少就是多少）。⇒ `break-all` + 窄屏降到 22px。
- 头部三组元素（品牌 / 两个视图 / GitHub）在 375px 摆不开、实测重叠。⇒ GitHub 链接 `hidden sm:inline`，沿用这个文件原本对副标题的同一手法。

## 2026-10-09 · 公司选择与账户

延续研究工作台。主路径改为「搜公司 → 选范围 → 跑分析」。公司选择使用名称、六位代码与数据源拼音搜索，键盘上下选择、Enter 添加、Escape 关闭；已选公司以名称 + 等宽代码显示，可以移除。批量粘贴作为折叠的专家入口保留，支持中英文分隔符，提交前去重。目录搜索不代表核查数据覆盖。

账户区域使用同一套墨绿、纸白与细边框，明确登录/注册/邮件待确认/配置缺失/退出错误。前端不保存密码；Supabase 管理会话。切换用户时重建任务视图，活动任务键按用户隔离。SSE 与下载统一经带用户 Bearer 的 fetch，不把令牌放进 URL。
